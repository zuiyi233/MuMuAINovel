## 2026-02-14 — IndexedDB schema expansion (organizations/relationships/foreshadows)
- `frontend/src/utils/indexedDb.ts`: bumped `DB_VERSION` to **2** and added an explicit `buildSchemaV2()` upgrade hook (`oldVersion < 2`) to keep future migrations additive and predictable.
- Stores are browser-scoped with composite primary key `['browser_id','id']`.
- Index patterns used for list screens:
  - organizations: `by_browser_project_updated`, `by_browser_project_parent`, `by_browser_project_level`
  - organization_members: `by_browser_organization`, `by_browser_organization_rank`, `by_browser_organization_updated`, `by_browser_character`
  - relationships: `by_browser_project_updated`, `by_browser_project_from_to`, `by_browser_project_to_from`
  - foreshadows: `by_browser_project_updated`, `by_browser_project_status_updated`, `by_browser_project_plantChapter`

## 2026-02-14 — localDb wrapper conventions

- `localOrganizationMembers.listByOrganization()` uses the rank-sorted composite index (`by_browser_organization_rank`) and `IDBKeyRange.bound([browserId, orgId, -Infinity], [browserId, orgId, Infinity])`.

## 2026-02-14 — Shadow sync v1 wiring
- Backend: added `POST /api/sync/shadow` to accept a full project bundle and perform **idempotent** upsert + per-project full-replace delete based on payload ID sets.
- Frontend: added `localShadowDump.projectBundle(projectId)` to gather project + outlines/chapters/characters/organizations/organization_members/relationships/foreshadows from IndexedDB and post via `syncProjectShadow(projectId)`.

## 2026-02-14 — Shadow sync v1 backend semantics
- Router: `backend/app/api/sync.py` mounted as `/api/sync/shadow` (router prefix `/sync`, app prefix `/api`).
- Authorization: `verify_project_access(project_id, request.state.user_id, db)` gates all operations.
- Safety validations added before writes:
  - Any payload entity with `project_id` must match `project.id`.
  - References are verified within the same project (payload IDs or DB IDs for that project):
    - `organizations.character_id` must exist (payload characters or DB characters).
    - `organization_members.organization_id` must exist (payload organizations or DB organizations).
    - `organization_members.character_id` must exist (payload characters or DB characters).
    - `chapters.outline_id` must exist (payload outlines or DB outlines).
    - `relationships.character_from_id/to_id` must exist (payload characters or DB characters).
    - `foreshadows.*_chapter_id` must exist (payload chapters or DB chapters).
- Full-replace deletion is strictly per-project; special-case for `organization_members` uses the set of organization IDs belonging to the project to scope deletes.
